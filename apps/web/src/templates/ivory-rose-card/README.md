# Oq atirgul — static image invitation

An original generated 5:7 portrait wedding/fotiha design. This is a flat invitation
image, with no animation, third-party runtime, external assets or public webpage.
Only Templates, Studio and Taklifnomalarim expose it; homepage selections are
unchanged. Image templates explicitly reject web publishing and Click checkout.
Downloads are free until the user approves a separate payment follow-up.

The background was created with the built-in imagegen tool on 2026-11-03. Its
original generated bytes are preserved in `assets/background.png`. Local regular
and italic EB Garamond fonts are packaged beside it; both include Cyrillic glyphs.
The editorial revision adds private, local Great Vibes subsets for Latin,
extended Latin, Cyrillic and extended Cyrillic names. No font service is used.
The complete generation prompt is in `generation-prompt.md`.

## Field map

`layout.ts` owns final-image pixel coordinates, bounds and font fitting. One server
renderer uses it for both the 750 × 1050 watermarked preview and 1500 × 2100 PNG.
No sample values are defined in the layout. All catalog artwork uses the canonical
shared preview JSON through `createTemplatePreviewSample`.

| Composition group | Invitation source | Treatment |
| --- | --- | --- |
| Occasion heading | `content[locale].eventLabel` | Tracked serif, 485 / 55 px |
| Name pair | `content[locale].people[0..1]` | Calligraphy, 595 / 170 and 810 / 170 px; ampersand between fine rules |
| Invitation text | `content[locale].message` | Compact centered paragraph, 1010 / 160 px |
| Date and time band | `startsAt`, `timezone`, default locale | Large day; month/year alongside; weekday/time in the third column, between rules at y1205 and y1380 |
| Venue group | `content[locale].venueName` | Small localized label and larger left-aligned venue, y1420–1565 |
| Address and landmark | `content[locale].address`, `.landmark` | Left-aligned supporting text, 1580 / 115 px |
| Location QR | Yandex destination from shared `venue`; written-address search fallback | x345 / y1735 / 210 px, corner brackets and localized caption alongside |

The original artwork is unchanged. `composition.ts` supplies the small engraved
details that connect the name, date and QR groups; these are template-owned code,
separate from the invitation data adapter. The type column moves slightly right
of the floral upper-left mass; the left-aligned venue and QR balance the lower-right
roses. Fine rules share exact alignments with the date columns and lower text.
This design intentionally omits greeting, hosts and
contacts; Studio hides those inputs and shared normalization strips them before
persistence. Supported fields and QR capability are declared in the typed capability
registry. Required image fields are listed in `IMAGE_REQUIRED_FIELDS`: people,
event heading, invitation text, date/time, timezone, venue name and location
(written address or map). Each future design owns its own visual hierarchy.
The QR is generated locally with a quiet zone. The existing server adapter supplies
the immutable eight-character Fotiha short URL; both short payloads and canonical
Yandex fallbacks are decoded in verification. No external QR service is involved.

Empty optional slots stay blank. Text wraps and shrinks within each slot's readable
minimum; oversized content produces a 422 error rather than clipping. Dates use
the shared formatter, including explicit Uzbek Cyrillic month names. Localized
names remain manually authored; the UI renders/downloads the default locale with
no language controls. Existing stored translations remain preserved.

## Ownership and finalization

Server-owned PNG download requires an authenticated owner, canonical saved revision,
enabled locale, complete content and published/event-compatible catalog row.
The first successful render/finalization locks the event identity/design and
sets the approved date and existing event-day editing deadline, but does not publish
an invitation webpage or allocate a slug. Location/date/time corrections and repeated
downloads remain available within the existing bounded editing policy; later dates
require administrator approval. Client-supplied export timestamps are
ignored. Metadata/audit finalization is transactional and only follows rendering;
failed rendering does not lock the invitation.

Preview responses are watermarked pixels with private/no-store headers. Source
artwork/fonts live outside `public/`; no clean personalized render or editable
layers are sent as part of previews. The sample-only public catalog poster is a
real full-card render. Screenshots and subsequent editing of downloaded images
cannot be prevented.
