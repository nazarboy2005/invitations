# Velora source package

This folder contains the captured Invitate Velora template and its app adapter.

- `source/` keeps the captured page, styles, script, font stylesheet, and listed visual assets for reference. The manifest advertises `reports/new-sites/Invitate/14-source.png`, but that screenshot is absent from this checkout. A full provider-folder search found no additional Velora-specific JavaScript chunk or bundle beyond `assets/js/velora.js`; AOS 2.3.1 is the captured animation dependency.
- `index.html` and `assets/` are the isolated local runtime package. They retain the source layout, typography, artwork, animations, calendar, countdown, and user initiated music control.
- `assets/js/velora-adapter.js` maps the shared invitation contract into the source DOM and translates interface text for Uzbek Latin, Uzbek Cyrillic, Russian, and English. The React renderer sends creator data to this adapter for both preview and public rendering.
- `preview.png` is a 480×860 capture of the packaged renderer opening page with the shared catalog fixture injected ephemerally. Capture details and SHA-256 are recorded in `preview.provenance.json`; fixture content is catalog artwork only and is never saved or published.

The adapter maps names, event date and time, greeting, invitation text, venue and map URL, agenda, dress code and colors, story chapters, gallery items, RSVP, a Telegram or phone contact, optional music, and host names. Agenda and gallery items retain their order; the gallery carousel reuses the captured dress-code slider structure, maps alt text and captions, and hides when no creator gallery is present. Missing optional content is hidden. Preview music can come from the shared preview fixture only; it is not saved as creator content. Reapplying invitation data preserves current playback when the music URL is unchanged, and resets the control when that URL changes or music is removed.

The copied runtime retains the captured HTML structure and the captured CSS byte-for-byte after its preview asset base URL is rewritten locally; it adds a scoped reduced-motion override. Source-level adaptations are isolated to `index.html` (local font/AOS links and localized on/off music icons), `assets/vendor/ibm-plex-serif.css` (all 76 source-declared font files localized), `assets/js/velora-adapter.js` (contract data binding and service controls), and `assets/css/velora.css` (gallery captions and reduced-motion handling). Source HTML, CSS, and `velora.js` in `source/` remain unchanged, with hashes checked by the focused test. The copied provider footer, analytics and provider runtime were removed. Provider form submission was replaced with the app RSVP endpoint; no captured sample guest responses are used. The source sample copy, names, dates, locations, and dress-code model/couple photos are not used as invitation data. The source HTML had five dress-code carousel photos at external `wow-card.ru` URLs, but those images were absent from the capture manifest; the isolated package uses creator gallery items in that slot instead. The optional source audio `/music/0341.aac` was also absent from the archive and is not reused; creator or shared preview music is used. The `music-off2.png` control icon was referenced by the source but omitted from the manifest because it loads only on music activation; the exact referenced image is localized at `assets/images/music-off2.png` and its SHA-256 is recorded in `assets/provenance.json`. Original capture files remain unchanged.

Velora has no gift/to'yona section or public guest-wishes feed in its source layout; those fields have no visible control. Its source has one contact block, so the adapter displays one Telegram or phone contact. RSVP supports one guest per submission and an optional note.

The RSVP source markup contains both an intro paragraph and a radio-group question label. The adapter hides the intro paragraph and keeps the single localized radio-group question, avoiding duplicate question text and overlap with the per-guest hint.
