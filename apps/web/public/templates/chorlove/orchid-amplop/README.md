# Orchid Amplop

Orchid Amplop is isolated under this folder. Its original stylesheet is preserved verbatim from Chorlove component module 482485, with the full template markup, source motion, seven recovered source images, and local Comfortaa/Allura subsets. The iframe adapter is separate from the template package. No Chorlove site runtime, authentication, analytics, or sample invitation record is copied into the renderer.

## Source graph and assets

The captured preview frame is opening-only. Its route component is module 482485 and entry shim 838250 in 0v0-3ulc~exde.js; module 437202 in 0d2h69c7a3snv.js supplies the default gallery. The restored source frame references 16 local JavaScript chunks. Its component chunk matches the captured provenance SHA-256. The original source image directory contains eight files; all eight are byte-identical to the package. Recursive exact-name search across the recovered provider archives found one same-name `divider.svg` in Taklifiy's Sacred Garden; its SHA-256 differs from Orchid's exact source image. The other six referenced image names are absent from those archives. All seven exact Orchid source URLs return HTTP 200 and their responses match the packaged bytes and recorded hashes. Per-image status, URL, format and hash are in source/provenance.json. The package manifest and all nine font subsets validate against their SHA-256 values. The embedded CSS matches the recorded source hash.

The portrait catalog image is a 450×800 capture of the actual opener using the canonical catalog fixture, without app chrome. The remote metadata image is not used because it contains fixed couple names and provider UI. Both typed catalog rows point to assets/catalog-opening.png.

## Shared invitation mapping and source sections

- Localized couple names, host names, greeting and personalized guest greeting, message, event date/time/timezone/countdown/calendar, venue/address/map, and repeatable program are supplied by the shared invitation adapter.
- Source-designed sections are the opener/hero, couple portraits, date/program, story, gallery/lightbox, gift card, wishes, RSVP, and footer contacts. Story, gallery, gift, wishes, and RSVP visibility follows available contract data and the source's optional-section behavior. The captured source has no dress-code section or extra-family-people section; the Orchid adapter suppresses those generic platform insertions.
- The source has one section heading for its story and no separate headings on story cards. The adapter maps creator story text into its two original text cards and does not render contract titles as extra headings.
- The shared contract has invitation-wide contacts but no separate groom and bride social fields. Telegram/Instagram contacts are therefore reused for both profile links when present and also remain in footer contacts; do not interpret them as independently assigned accounts.
- The catalog/initial-selection fixture uses the six original Orchid gallery images in the exact source order (gallery-2, gallery-1, gallery-3, gallery-6, gallery-4, gallery-5). They are ephemeral. Creator uploads replace them; public invitations never receive source demo photos. Source portraits and story images are preview-only fallbacks because the shared contract has no fields for those image slots.
- Catalog and blank initial-selection previews explicitly set `sampleGallery`; only that sample mode may use the source gallery, story, couple, and venue photos. Authored creator previews and public invitations use uploaded gallery images when present and hide the gallery when empty; source demo portraits/story photos and venue-card photos are not injected into those views. The source venue card uses `gallery-5.webp`.
- Gift card number, cardholder, and optional note use the source gift-card reveal/copy layout. The platform receipt-upload form is attached inside the revealed gift card when enabled; it remains hidden when receipts are disabled.
- RSVP presents only guest name and attending/not attending. The adapter submits the existing fixed party size (1 for attending, 0 for not attending); it does not prompt for guest count. RSVP/wishes API release checks are tracked separately and are not publication blockers under the current decision.
- Uzbek Latin, Uzbek Cyrillic, English, and Russian controls are localized. The Uzbek Latin opener now matches the captured source wording, including the prayer, blessing, invitation line, and wedding label.

## Fidelity and motion

The source component declares gallery image scale 0.96→1 on entry and 1→0.96 on exit, with opacity 0→1/1→0; backdrop opacity uses the same source spring. The adapted WAAPI spring uses Framer Motion's defaults (stiffness 100, damping 10, mass 1); the current implementation's generated scale spring lasts 350 ms and opacity spring lasts 1083 ms. The previous 717 ms scale measurement was for the older 0.8→1 approximation and is superseded. Integrated local preview checks at 390×844 opened the gate and gallery in normal and reduced-motion modes. Reduced-motion CSS stops opener/reveal/pulse/arrow animations and transitions while leaving reveal content visible; the bridge also skips its gate, gift, and lightbox motion. The source keeps animating under reduced motion, so this is an accessibility adaptation rather than exact reduced-motion parity. The recovered untouched `preview-frame.html` was served locally and compared with the package at 1280×720 after the opener settled: prayer, blessing, kicker, couple names, date, fonts, and their bounding-box positions match. The current public source preview URL still returns 404; the local comparison used the captured archive page and exact component chunk.

Normal/reduced runtime checks also confirmed six preview gallery cells, loaded local images and fonts, immediate reduced-motion opening, and no visible dress-code or extra-people section. The recovered source scrolls within a viewport-sized container with a visible/reserved scrollbar; the package now does the same, and opener/back-to-top behavior targets that container. Both scrollers measure 1265px content width in a 1280px viewport. The source and package opener were visually compared in the same viewport; the opening art, copy, typography, and element placement align. The lightbox backdrop, image bounds, close icon, and source gallery scale endpoints were checked against the source declarations. The restored package contains six source dividers. The seven missing image URLs in the local archive were fulfilled with the exact verified packaged bytes, allowing downstream geometry comparison. With source-matched copy, contacts, and six wishes, the source and package match section starts/heights and total scroll height at 1280×720: starts 0, 767, 1763, 2910, 3944, 4953, 5296, 6893, 7351; total height 7850px. The desktop story grid uses an 18px gap (the base/mobile rule is 16px); source CSS also confirms event-card padding 22px×25px and lightbox bounds 94vw/1100px and 88dvh. Source captures remain untouched.
