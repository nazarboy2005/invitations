# Modern Floral source integration

The packaged page keeps the captured Modern Floral HTML structure and its shared Chorlove styles. `source-motion.js` ports the choreography from the original route chunk recorded in `source-assets.provenance.json`; `bridge.js` remains responsible for invitation data and platform actions.

## Source behavior retained

- Opening greeting reveal, curtain collapse, and overlay fade at the original 1.45 s / 2.25 s / 3.0 s timing.
- Thirty-four drifting petals with the source's deterministic positions, delays, duration, rotation, and sway.
- Viewport-based section reveals, including source stagger, blur, scale, and translation treatments.
- Floating floral ornaments, the opening halo rotation and heart pulse, the couple-divider pulse, the countdown heart pulse, the scroll cue, and wishes marquee.
- Lightbox transitions and hover/press feedback for music and map controls.
- Reduced-motion mode makes the content visible without starting decorative motion.

The captured first-page catalog artwork is packaged as `catalog-opening.jpg`; its original URL, dimensions, and SHA-256 are recorded in `source-assets.provenance.json`. The original route’s shared `DEFAULT_PREVIEW_GALLERY_IMAGES` are six Orchid Amplop gallery photos in the source order 2, 1, 3, 6, 4, 5. The existing Chorlove package files are byte-identical to the captured source files and are used only by `preview-sample.json` for catalog and initial template-selection previews. They do not enter creator invitations or published content. Creator/public galleries use invitation images only, and the gallery section is hidden when the invitation contains no uploaded images.

## Verification status

The captured route HTML and compiled route chunk in the recovered source archive match the provenance SHA-256 hashes. Static source-to-runner checks cover all captured reveal variants, delays/staggers, 34 petal parameters, floating ornaments, heart/halo/scroll loops, music/map hover and press states, and the wishes marquee. The runner also exposes reduced-motion handling; the captured route chunk has no corresponding reduced-motion branch, so this is an accessibility adaptation. A live OS reduced-motion preference change now cancels active Web Animations and removes an open animated lightbox; switching back keeps the already revealed content visible without replaying the opening. Same-browser 390×844 captures previously compared the opening and couple-name section; during this audit the source and package were also scrolled through their next reveals. The captured HTML archive is a recovery snapshot rather than a stable original live route: its archived Next runtime reports a React hydration error, and the different invitation sample data prevents pixel-by-pixel content matching.

The packaged preview exposed a `ReferenceError` in `renderWishes`: it called an undefined `data()` accessor twice before the existing render could finish. All three wishes-data reads now use the bridge's `d()` accessor. A fresh packaged preview tab now renders through guest wishes, RSVP, and the footer with no browser console errors; the focused regression test rejects any unresolved `data()` call in the bridge. This is a platform adapter correction, not a change to captured source styles or motion.

The preview root's `overflow:hidden` override prevented vertical scrolling; it now hides horizontal overflow while preserving vertical scrolling. A fresh normal preview was wheel-scrolled from the opening through the countdown and contact sections to the gallery and footer. The `qaReducedMotion=1` preview also kept the page scrollable, suppressed the falling petals and transitions, and left all 13 captured sections available. Gallery data previously populated only `.grid` (the mobile layout), leaving the desktop `md:grid` cards empty. The adapter now updates both responsive layouts.
